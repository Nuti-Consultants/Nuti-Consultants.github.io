What we build

Standards-based network functions and the tooling around them — written from specification, tested against it, and operated in production. We work from the 3GPP and IETF documents directly rather than from a vendor’s interpretation of them.

Mobile core network functions

Control-plane and user-plane elements for EPC and 5GC, built to specification in Go or C.

  • GTP-C / GTP-U — 3GPP TS 29.274, TS 29.281
  • PFCP and the N4 interface — TS 29.244
  • Session state, HA and failover design

Signalling & interconnect

SS7 and Diameter elements for roaming and partner interconnect, including the parts vendors leave out.

  • SS7 / SIGTRAN — M3UA (RFC 4666), SCCP, TCAP, MAP
  • Diameter routing — RFC 6733, S6a, IMSI translation
  • RADIUS (RFC 2865) and NAPTR DNS (RFC 3403)

Test & conformance tooling

Traffic generators and fault injectors that reproduce real interop failures in a lab, before a partner finds them.

  • Specification-compliant traffic generation
  • Peer simulators with deliberate fault injection
  • Interop and regression suites in CI

Platform & lifecycle engineering

Running stateful network functions on Kubernetes, and the install and upgrade tooling that makes it repeatable.

  • Helm and overlay-based delivery, secrets management
  • Day-1 install gates and day-2 upgrade procedures
  • Infrastructure-as-code with drift detection

Observability for network functions

Instrumentation designed with the protocol in mind, not bolted on afterwards.

  • In-process metrics, session and cache gauges
  • Protocol-layer active probing
  • Alert hygiene — fewer alerts that mean more

Carrier integration

Bringing a new roaming or MVNO partner up, from addressing and peering through to first live traffic.

  • Interconnect design, BGP peering, IPsec
  • Partner turn-up automation
  • Packet-level fault diagnosis across the path

How we work

We start from the specification. Most interop problems in a carrier network come from two implementations reading the same clause differently, so the first question on any engagement is which document governs, and what it actually says.

We prefer to leave a client with something they can operate without us: source they own, tests that prove it, and a runbook written for the person on call at 2am rather than for the person who built it.

Engagements run from a short specification review or interop investigation through to building and handing over a complete network function.
