The problem

A carrier interconnecting with many roaming and MVNO partners ends up with a routing problem that no single vendor product solves. Each partner presents different addressing, different APN conventions and a different idea of which identifiers are authoritative. Traffic has to be steered on a combination of all of them, and a partner having a bad day must degrade its own traffic and nobody else’s.

What we built

A GTP proxy, written from the specification

A carrier-grade GTP proxy in Go handling both GTPv1 and GTPv2, control plane and user plane. Routing is a layered hierarchy rather than a flat table: a composite match first, then APN, subscriber group, pinned assignments, individual subscriber, and finally network and country codes — so the common case resolves immediately and the unusual case still resolves correctly.

  • Peer path management to TS 29.274, with automatic blacklisting when a peer stops answering echo requests, and controlled recovery when it returns.
  • Per-peer token-bucket rate limiting, so one partner’s retransmit storm cannot consume the path.
  • A zero-allocation hot path on the user plane, because garbage collection pauses are visible as jitter at this layer.
  • Session state in a Sentinel-backed store, with failover that preserves established bearers.

Signalling either side of it

A GTP proxy only solves one interface. The same engagement covered the signalling around it: Diameter routing agents in C on freeDiameter, performing subscriber-identifier translation between carrier and MVNO numbering plans, and a signalling transfer point on an Osmocom base carrying SS7 for roaming — extended with roaming-partner address hiding, global-title pattern routing, and MAP/TCAP dialogue correlation.

The data layer underneath

Routing decisions are only as fast as the lookups behind them. The proxy carries its own hierarchical data layer with multi-tier caching, delta synchronisation rather than full reloads, and versioned schema migrations with rollbacks — so a routing change is a deploy, not an outage.

How it holds up

Load-tested past 100,000 concurrent sessions. More usefully, it ships with a fault-injecting peer simulator: the failures that matter at an interconnect are a partner responding slowly, responding wrongly, or responding with a sequence that should never occur, and those are reproduced in a lab rather than discovered in production.
